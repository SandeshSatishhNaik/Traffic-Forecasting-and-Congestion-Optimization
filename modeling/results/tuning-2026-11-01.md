# Phase 2: fine-tuning the graph model (1 November 2026)

**Procedure.** Random search over hidden size, embedding size, dropout, learning rate, weight decay, batch size and number of input lags (`tune.py`). Every configuration was trained for the 15, 30 and 60 minute models with 3 seeds and scored by the validation error (mean absolute error as % of normal speed). **Only data before the test week was used:** train before 11 Oct, validate 11 to 17 Oct. The chosen configuration was then run once on the test week (25 to 31 Oct) with 5 seeds, together with all other models, using the same settings for the networks with and without a graph.

**Outcome.** 30 random configurations plus the default. Validation error 8.784% (default) vs 8.627% (chosen); the worst configuration scored 9.52%. Settings matter little for this model; most of the gain comes from the road graph (see `phase2-models-tuned-2026-11-01.md`).

Chosen: hid = 64, emb = 4, drop = 0.2, lr = 0.003, wd = 0.0, batch = 32, lags = 3.

Tuning improved the 30 and 60 minute errors by about 1.5% and left 15 minutes unchanged, and it made training more stable: the standard deviation over seeds fell from 0.03 to 0.10 km/h to 0.02 to 0.03 km/h. Learning curves (`results/tuning-2026-11-01.json`, key `curves`) show training and validation errors close together, so there is no heavy over-fitting.
